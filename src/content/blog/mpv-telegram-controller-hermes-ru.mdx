# Управляю mpv на ТВ домашнего сервера через Telegram и Hermes-агента

Мой домашний сервер стоит в гостиной и подключён к телевизору по HDMI. Долгое время единственным способом что-то запустить было встать, переключить клавиатуру и набрать команду. Для одного фильма — нормально. Для «включи мне мультики фоном, пока готовлю» — нет.

Поэтому я повесил всю эту конструкцию на Telegram. Теперь телевизор — это медиа-приставка, которой я управляю с телефона, то есть с той же поверхности, с которой делаю всё остальное. Над одним инстансом mpv живут два пути управления:

- **Quick-команды** (`/mpv_pause`, `/mpv_play lain`) — мгновенные, без вызова LLM, ноль токенов.
- **Естественный язык** («поставь на паузу», «включи что-нибудь про роботов») — идёт через [Hermes-агента](https://hermes-agent.nousresearch.com/) (Nous Research), на модели `hermes-medium` через [nanogpt](https://nano-gpt.com/). У меня подписка за **$12/мес** — для личного пульта от телевизора этого с запасом, но ниже есть важная оговорка.

В этом посте я разбираю, как всё это собрано, какой IPC-фокус заставляет всё работать, и какие тонкие подводные камни сожрали мне несколько часов.

## Архитектура

```
┌─────────────┐       ┌──────────────────┐       ┌──────────────┐
│  Telegram   │──────▶│  Hermes Gateway  │──────▶│   mpvctl.sh  │
│  (телефон)  │       │  (homeserver)    │       │   (скрипт)   │
└─────────────┘       └────────┬─────────┘       └──────┬───────┘
                               │                        │
                       (только LLM-маршрут)             │ JSON-IPC
                               │                        ▼
                       ┌───────▼────────┐       ┌──────────────┐
                       │  hermes-medium │       │     mpv      │
                       │  через nanogpt │       │ (i3 ws 10)   │
                       └────────────────┘       └──────┬───────┘
                                                       │ HDMI
                                                       ▼
                                                 ┌──────────┐
                                                 │    ТВ    │
                                                 └──────────┘
```

Ключевая идея: **сообщение из Telegram либо короткозамкнуто на shell-скрипт (ноль токенов), либо уходит в LLM (если запрос требует понимания)**. Оба пути в итоге говорят с одним и тем же инстансом mpv через Unix-сокет.

## Сторона mpv

mpv работает в X-сессии сервера (`DISPLAY=:0`), закреплён за рабочим столом i3 №10. Запускается с IPC-сокетом, чтобы любой, у кого есть доступ к shell, мог им управлять:

```bash
mpv --input-ipc-server=/tmp/mpv-socket \
    --force-window \
    --playlist=/path/to/something.m3u
```

`--input-ipc-server` — это магический флаг. mpv открывает `/tmp/mpv-socket` как Unix-сокет и принимает JSON-команды. Пауза превращается в:

```bash
python3 -c "
import socket
s = socket.socket(socket.AF_UNIX)
s.connect('/tmp/mpv-socket')
s.send(b'{\"command\":[\"set_property\",\"pause\",true]}\n')
s.close()
"
```

(Хотелось бы использовать `socat`, но он на этом сервере не установлен. Пусть будет Python.)

`--force-window` важен: без него mpv отказывается открывать окно, пока не начнёт грузиться медиа — и гонка «плейлист пустой / только что стартанули» становится видимой. С ним окно всегда есть.

### Обёртка mpv-runner

Когда mpv запускается из неграфического контекста (Telegram-бот, systemd, tmux на другом tty), ему нужно явно экспортнуть `DISPLAY` и i3 IPC-сокет. Иначе: звук есть, окна нет. Я это понял на собственной шкуре.

Обёртка `/tmp/mpv-runner.sh`:

```bash
#!/bin/bash
export I3SOCK="/run/user/1000/i3/ipc-socket.2012"
export DISPLAY=:0
exec mpv "$@"
```

Подвох: `/tmp` на этой машине — tmpfs, поэтому обёртка исчезает при перезагрузке. Скрипт `mpvctl.sh` проверяет её существование перед каждым запуском и пересоздаёт, если её нет. Это была баг №1 в категории «бот говорит что запустил, а ничего не произошло».

## Диспетчер mpvctl.sh

Всё, что приходит из Telegram, маршрутизируется через один shell-скрипт: `~/.hermes/scripts/mpvctl.sh`. Он принимает подкоманду (`pause`, `play`, `volup`, `list`, ...) и либо общается с IPC-сокетом, либо — для `play` — запускает новый инстанс mpv.

Самое интересное — кейс запуска. Наивно:

```bash
nohup /tmp/mpv-runner.sh --playlist="$MATCH" ... &
disown
```

Это отлично работает, когда вы запускаете скрипт из терминала. И **ломается**, когда gateway запускает его через `asyncio.create_subprocess_shell` с захваченными пайпами — нет управляющего TTY, от которого `nohup` мог бы отцепиться, и скрипту вместе с mpv прилетает SIGTERM сразу после выхода скрипта. Результат: код возврата -15, пустой вывод, mpv не появляется.

Лечится через `setsid`:

```bash
setsid /tmp/mpv-runner.sh \
    --playlist="$MATCH" \
    --input-ipc-server="$SOCKET" \
    --force-window \
    </dev/null >/dev/null 2>&1 &
```

`setsid` форкает новую OS-сессию, полностью отделённую от того, что запустило скрипт. В сочетании с `</dev/null >/dev/null 2>&1` (которое отвязывает унаследованные дескрипторы пайпов) скрипт мгновенно возвращается, а mpv продолжает работать.

## Связь с Telegram: Quick-команды

Это было жёстким требованием на старте: повседневные глаголы — пауза, продолжить, перемотать, показать список — **не должны** дёргать LLM. Я нажимаю их десятки раз в день, и если бы каждый тап по `/mpv_pause` уходил в токены, я бы пялился на usage-панель nanogpt уже к среде. Поэтому нужен был маршрут полностью без LLM.

Hermes ровно это поддерживает через top-level ключ конфига `quick_commands` в `~/.hermes/config.yaml`. Всё, что туда зарегистрировано, матчится Telegram-gateway *до* агентского цикла, диспатчится как обычный shell-exec, а stdout скрипта отправляется обратно в Telegram как ответ. **Ни одного вызова модели. Ни одного токена. Ноль в недельную квоту. Мгновенно.**

Quick-команды не «включаются по умолчанию» в том смысле, что им нужны записи — нет автоматического моста из «эта операция повторяется» в «эта операция получит shell-шорткат». Каждую опт-инишь явно — добавляешь в блок `quick_commands:`. У меня он выглядит так:

```yaml
quick_commands:
  mpv_pause:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh pause
  mpv_unpause:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh unpause
  mpv_quit:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh quit
  mpv_volup:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh volup
  mpv_voldown:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh voldown
  mpv_mute:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh mute
  mpv_list:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh list
  mpv_info:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh info
  mpv_fwd:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh fwd
  mpv_back:
    type: exec
    command: /home/username/.hermes/scripts/mpvctl.sh back
  mpv_play:
    type: exec
    command: /bin/bash /home/username/.hermes/scripts/mpvctl.sh play {{ARGS}}
  mpv:
    type: exec
    command: /bin/bash /home/username/.hermes/scripts/mpvctl.sh play {{ARGS}}
```

Здесь две неочевидные штуки:

1. **Подчёркивания, а не дефисы.** Telegram присылает `/mpv_list` как команду `mpv_list` (с подчёркиванием). Лукап в gateway — строгий, exact-match. Я потратил на это целый вечер: если в конфиге написать `mpv-list`, оно молча уходит в «Unknown command».

2. **Префикс `/bin/bash` у команд, которые запускают процесс.** Та же первопричина, что и с `setsid`. Gateway запускает это через asyncio subprocess с захваченными пайпами. Прямой путь к скрипту возвращает SIGTERM (-15) и mpv не запускается. Обёртка `/bin/bash` обходит non-TTY поведение asyncio. Команды без запуска процесса (`pause`, `volup` и т.д.) в этом не нуждаются — они корректно завершаются без spawn детей.

Плейсхолдер `{{ARGS}}` экранируется через `shlex.quote()` перед подстановкой, так что `/mpv_play "lain";rm -rf ~` не делает того, на что выглядит способным. Этот `shlex.quote` живёт внутри обработчика exec в gateway — вот соответствующий кусок `gateway/run.py`:

```python
# Sanitize env to prevent credential leakage —
# quick commands run in the gateway process which
# has all API keys in os.environ.
from tools.environments.local import _sanitize_subprocess_env
sanitized_env = _sanitize_subprocess_env(os.environ.copy())
proc = await asyncio.create_subprocess_shell(
    exec_cmd,
    stdout=asyncio.subprocess.PIPE,
    stderr=asyncio.subprocess.PIPE,
    env=sanitized_env,
)
stdout, stderr = await asyncio.wait_for(proc.communicate(), timeout=30)
output = (stdout or stderr).decode().strip()
# Redact any remaining sensitive patterns in output
if output:
    from agent.redact import redact_sensitive_text
    output = redact_sensitive_text(output)
return output if output else "Command returned no output."
```

Здесь сразу три приятные эшелонированные защиты, которые мне не пришлось писать самому:

- **Санитизация окружения** вычищает API-ключи из `os.environ` до запуска скрипта — мой shell-скрипт даже теоретически не сможет случайно прокинуть `env | tg-message` куда-нибудь не туда.
- **Жёсткий таймаут 30 секунд** не даёт зависшему скрипту заклинить командный цикл gateway.
- **Редакция вывода** проходит по тому, что напечатал скрипт, и зачищает всё похожее на API-ключ — до того, как это вообще достигнет Telegram.

Для инструмента, который превращает «всё окружение процесса моего Telegram-бота» в «shell-скрипты, запускаемые кем угодно из `allowed_chats`» — это очень спокойный набор гарантий.

## Quick-команды в работе

После регистрации этих команд (и не забыв вызвать `deleteMyCommands` для всех scope-овых остатков — они молча перекрывают default scope), меню моего Telegram-бота стало полноценным пультом:

| Команда | Что делает |
|---|---|
| `/mpv_pause` | Пауза |
| `/mpv_unpause` | Продолжить |
| `/mpv_quit` | Стоп |
| `/mpv_volup` / `/mpv_voldown` | Громкость ±10 |
| `/mpv_mute` | Тоггл mute |
| `/mpv_fwd` / `/mpv_back` | Перемотка +30с / -10с |
| `/mpv_list` | Список плейлистов |
| `/mpv_info` | Что сейчас играет |
| `/mpv_play <имя>` | Fuzzy-поиск и запуск плейлиста |

Команда `play` ищет в трёх папках по порядку: `~/Videos/cartoons/playlists/`, `~/Videos/movie/playlists/`, `~/Videos/shows/playlists/` — и берёт первый `.m3u`, чьё имя содержит поисковый аргумент (без учёта регистра). То есть `/mpv_play lain` находит `serial-experiments-lain.m3u`, `/mpv_play deadwood` находит `Deadwood.m3u` и так далее. Если передать число — оно индексирует в отсортированный список из `/mpv_list`.

## LLM-маршрут: nanogpt + hermes-medium

Quick-команды покрывают 95% того, что мне нужно. Оставшиеся 5% — это запросы, которые требуют реальной интерпретации:

- «включи что-нибудь про роботов»
- «как там назывался тот сериал про постапокалиптическую трассу»
- «перемотай к моменту, где врубается музыка»

Для этого я настроил Hermes использовать модель **`hermes-medium`** на эндпоинте **[nanogpt](https://nano-gpt.com/)** (OpenAI-совместимый API). У меня **подписка за $12/мес** — для болтливого пульта от телевизора фикс-тариф намного приятнее, чем оплата по токенам. К тому же nanogpt отдаёт ещё кучу open-weight моделей за тем же ключом — можно при желании A/B-тестить другие модели из `model-presets.json`.

Провайдер в `~/.hermes/config.yaml`:

```yaml
providers:
  nanogpt:
    api_key: sk-nano-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
    base_url: https://nano-gpt.com/api/v1
```

И запись пресета модели, которая выбирает `hermes-medium` на этом эндпоинте (`~/.hermes/model-presets.json`):

```json
{
  "id": "nano-medium",
  "label": "⚡ Nano GPT / Hermes Medium",
  "provider": "custom",
  "model": "hermes-medium",
  "base_url": "https://nano-gpt.com/api/v1"
}
```

Переключение — `/model nano-medium` в любом чате Hermes. Gateway записывает выбор обратно в `model-presets.json` в поле `current`, поэтому это переживает рестарты.

Когда сообщение не подпадает под quick-команду, gateway отдаёт его модели — но с подгруженным в контекст mpv-скиллом. Скилл лежит в `~/.hermes/skills/productivity/mpv-playlist-controller/SKILL.md` — это markdown-файл с frontmatter, который учит модель тем же операциям, что знает shell-скрипт, плюс логике fuzzy-поиска по файлам, плюс даёт ей разрешение вызывать `terminal()` с `background=true`, чтобы прямо так стартовать mpv через естественный язык:

```yaml
---
name: mpv-playlist-controller
description: Control mpv media player for playlists. List, play, pause, stop, mute cartoon playlists from Telegram.
trigger: "play playlist, mpv, pause video, stop video, mute video, list cartoons, list playlists, what cartoons do I have, show me cartoons, what playlist"
---
```

Строка `trigger` — это то, что заставляет скилл автоматически подгружаться, когда пользователь говорит «play lain» или «list cartoons». Никаких `/skill` вызывать не надо — gateway видит совпадающее ключевое слово и подсовывает SKILL.md в системный промпт модели. Референсы (`references/ipc-commands.md`, `references/user-environment.md` и т.д.) ссылаются из SKILL.md и подтягиваются по необходимости.

Два маршрута, один mpv. Скрипт делает то, что я повторяю изо дня в день; модель — то, что я говорю на ходу.

## Почему именно hermes-medium, а не что-то побольше

По нескольким практическим причинам:

- **Латентность.** Это интерактивный сценарий — я хочу, чтобы воспроизведение началось через пару секунд, а не после 10-секундного раунд-трипа к frontier-модели.
- **Задача маленькая.** Выбрать между `pause`, `seek`, `play <name>` и `list` не требует 200B-модели. `hermes-medium` справляется с запасом.
- **Цена.** Подписка nanogpt за $12/мес покрывает практически безлимитное использование *в этом масштабе*. Pay-per-token API стоили бы примерно столько же, если активно общаться, плюс к этому идёт тревожность от вечного счётчика.

Если у вас есть сервер пожирнее — controller для mpv против локального llama.cpp будет ещё дешевле и быстрее. nanogpt — это путь наименьшего сопротивления.

### Оговорка про «безлимит»

Фраза «$12 — это по сути безлимит» справедлива *именно для кейса с пультом от ТВ* — quick-команды полностью обходят модель, поэтому не тратят ничего из какой-либо квоты. Но есть деталь, которую стоит знать, если планируете использовать Hermes для чего-то ещё: подписка nanogpt — это не месячный тариф. Это **недельная квота на 60М входных токенов, которая сбрасывается каждые 7 дней, без переноса остатков**. Break-even — примерно 8.57М токенов в день.

Для трафика mpv-пульта это вообще не проблема. Но как только направляете Hermes на реальную агентскую работу — кодинг, длинные дебаг-чаты, всё, что накапливает контекст — расход резко ускоряется. Один интенсивный вечер может съесть четверть недельного лимита. Когда вы пробиваете потолок, nanogpt не выставляет доп. счёт — он понижает вас в приоритете, и модель становится заметно медленнее до сброса.

Я написал отдельный пост про то, [как читать status bar Hermes и какие настройки компрессии реально замедляют этот расход](/blog/hermes-status-bar-token-tweaks). TL;DR: снизить `compression.threshold` с `0.6` до `0.45`, серьёзно относиться к `/new` и не вставлять большие выводы инструментов обратно в разговор. Если планируете идти дальше, чем `/mpv_play lain` — стоит прочитать до того, как часы недельного сброса вас обгонят.

## Что я вынес из этой сборки

Если бы я делал это с нуля, я бы сэкономил себе следующее:

1. **Тестируйте путь запуска именно в той среде, через которую он будет реально вызываться.** Скрипт, который работает у вас в терминале — это не тот же скрипт, что работает под `asyncio.create_subprocess_shell` с `stdout=PIPE`. Используйте `setsid`, а не `nohup`.

2. **`/bin/bash <script>` не эквивалентно `<script>` под asyncio.** Даже с shebang. Я до конца не понимаю, почему — но поведение воспроизводится: bash-префикс работает, прямой путь даёт SIGTERM.

3. **Файлы в tmpfs исчезают при перезагрузке.** Не кладите ничего критичного в `/tmp` без проверки «существует ли, если нет — пересоздать». Обёртка `mpv-runner.sh` укусила меня дважды, пока я не добавил проверку.

4. **Имена команд Telegram-бота — через подчёркивания.** Всегда. Не пытайтесь быть стильным с дефисами.

5. **Scope в командах Telegram перекрывает default.** Если вы когда-то регистрировали команды с `{"scope": {"type": "all_private_chats"}}`, они переопределяют default в меню для приватных чатов. `getMyCommands` (default scope) будет вам врать про то, что реально видит ваш телефон. Вызывайте `deleteMyCommands` для каждого scope, который вы выставляли, либо перерегистрируйте под правильным.

6. **`--force-window` для mpv.** Без него пустой плейлист или медленная загрузка оставляют невидимое окно — и вы не понимаете, упал mpv или «думает».

7. **Полагайтесь на встроенные в gateway редакцию и санитизацию окружения.** Я им сначала не доверял и накручивал свой слой сверху. Потом прочитал `gateway/run.py` и понял, что gateway уже зачищает `os.environ` и пост-редактирует вывод subprocess. Мой дублирующий слой был просто лишней площадью атаки. Берите готовое.

## Каково этим реально пользоваться

Я сижу на диване. Открываю Telegram. Тапаю `/mpv_play lain` из меню бота. Через две секунды i3 переключается на рабочий стол 10 и на телевизоре стартует Serial Experiments Lain. Тапаю `/mpv_pause` когда звонит дверь. Тапаю `/mpv_unpause` после.

Если я забыл, что у меня в ротации — `/mpv_list` показывает всё. Если лень скроллить — «включи что-нибудь нуарное» уходит в LLM, и она выбирает за меня.

Суммарные усилия по сравнению с «нормальным» Android-TV-пультом: сопоставимы. Суммарная цена инфраструктуры: shell-скрипт, двенадцать строк YAML и подписка nanogpt за $12/мес. Суммарное удовольствие от того, что телевизор теперь управляется из `urllib.request`: существенное.
